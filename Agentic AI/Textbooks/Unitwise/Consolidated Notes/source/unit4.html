Part A — Implementing CWD in LLM-Based Systems (end of Chapter 6)

In traditional multi-agent systems, behaviours are explicit code; in LLM-based CWD systems they are controlled by prompts and interaction patterns. Three foundations: system prompts, instruction formatting, interaction patterns.

A1. System prompts and agent behaviour

System prompts are the fundamental configuration layer: unlike regular task prompts, they set an agent's persistent traits, boundaries and behavioural frameworks across its operational life cycle. In the travel planner every agent's system prompt must include:

  • Role definition and scope of responsibilities
  • Constraints and operational boundaries
  • Communication protocols with other agents
  • Decision-making frameworks specific to the role

Example: the flight booking worker's prompt has flight search parameters, pricing considerations, airline partnerships; the Coordinator's prompt has high-level planning and oversight. In CrewAI, role (functional boundaries) + backstory (context/expertise, e.g., "former airline revenue management expert...") together form a rich system prompt.

A2. Instruction formatting

Clear, consistent formats give reliable performance and inter-agent communication (instructions are interpreted via NL understanding). Key aspects:

A3. Interaction patterns

  • Message-passing protocols — structured agent-to-agent formats; clear handoff procedures between processing stages; error handling & recovery.
  • State management — awareness of current task status; tracking progress through multi-step processes; coordinating parallel activities.
  • Feedback loops — communicating success/failure; requesting clarification/more information; continuous improvement via interaction history.

A4. Chapter 6 summary & Q&A

CWD adapts early role-based research to LLM agents: well-defined roles, specialised workers under coordinator oversight, delegators managing distribution, effective communication/collaboration patterns, and implementation details (system prompts, instruction formatting) for operational success.

1. How does CWD enhance efficiency? Clear hierarchy — coordinator oversight, delegator distribution, specialised workers; enables parallel processing (core travel workers do bookings while analysis workers process data/search opportunities).
2. Role & backstory significance? Role = functional boundaries; backstory = context/expertise shaping decisions; together form the system prompt (e.g., aviation booking specialist + "former airline revenue management expert").
3. Core travel workers vs analysis & intelligence workers? Core: practical bookings/arrangements (flight, hotel, activity, transport). Analysis: data analyst, experience reflector, opportunity searcher — trends, feedback, new opportunities. Core executes immediate tasks; analysis improves decision-making and future performance.
4. Communication & collaboration aspects? Standard protocols (FIPA ACL), coordination mechanisms, negotiation/conflict resolution, knowledge sharing.
5. Instruction formatting? Structured input/output ensures unambiguous communication, clear task specifications, parseable results.

Part B1 — Focused System Prompts and Instructions for Agents

Focused instruction directs the agent: it lays down the objective, constraints and operating context; clarity and explicitness strongly influence performance.

B1.1 Defining objectives

Well-defined objectives are the foundation of intended functions/behaviours. Travel agent in customer service: "maximise customer satisfaction by providing personalised travel solutions and resolving queries/issues effectively", with components:

  • Personalisation — tailor to preferences, budgets, requirements; gather travel goals, interests, constraints.
  • Problem-solving — handle queries/issues: booking conflicts, travel advisories, alternatives for disruptions.
  • Effective communication — clear explanations of solutions/trade-offs; active listening; accurate interpretation of feedback.
  • Continuous improvement — monitor satisfaction and feedback; refine capabilities; adapt to trends.

Metrics: customer satisfaction ratings, successful resolution of queries/issues, quality of personalised plans. Objectives guide prioritisation within budget, time, logistical constraints.

Sample system prompt Objective: Act as an expert travel agent to provide personalised travel solutions while maximising customer satisfaction.
Core functions: gather & analyse preferences/constraints/budget; create personalised recommendations & itineraries; resolve travel issues & provide alternatives; communicate clearly and professionally; monitor satisfaction and adapt.
Constraints: stay within budget; prioritise customer safety; follow travel regulations; respect booking deadlines.
Behaviour: clear professional language; show empathy & patience; anticipate needs; transparent pricing; present options with pros/cons; document key requirements and deadlines.

B1.3 Contextual awareness

The backbone of intelligent behaviour: understanding environment, user needs and situational nuances; maintaining global and local contexts (international restrictions, seasonal weather, hotel policies, local transport).

  • Destination intelligence — peak seasons, local events, cultural significance (Japan: cherry-blossom season, festivals, regional weather → optimal dates).
  • Dynamic adaptation — real-time adjustment (flight cancelled by weather → assess alternative routes, impact on later bookings, propose solutions).
  • Cultural competence — dress codes at religious sites, dietary-friendly restaurants, local customs.

It goes beyond pattern matching: it transforms standard service into curated experiences.

States are "moment-in-time" knowledge about a task; the environment is the larger context (tools available, policies/rules, use-case details).

B2.2 Environment modelling

A detailed representation of the world in which the agent operates. Three fundamental questions: (1) What systems/services can the agent interact with? (2) What rules and constraints govern the interactions? (3) What changing conditions must it monitor and respond to?

Travel agent: connections to airline booking systems, hotel reservation platforms, payment processors; business rules; awareness of price changes and availability. A good model enables: informed decisions on current conditions, navigating complex systems, responding to changes, maintaining compliance, optimising within constraints.

Static environment elements (rarely change)Dynamic environment elements (need real-time monitoring)
Business rules & constraints: booking policies & procedures; payment processing requirements; cancellation/modification rules; service level agreements; regulatory compliance.

B2.3 Integration and interaction patterns

(1) Event-driven updates

Agent responds dynamically to environment changes; instead of constant polling it receives and processes events as they occur (airline updates flight status, hotel room becomes unavailable → immediate state updates).

class TravelAgentState:
    def update_booking_status(self, event):
        if event.type == "FLIGHT_CHANGE":
            self.check_dependencies()
            self.notify_customer()
        elif event.type == "WEATHER_ALERT":
            self.evaluate_alternatives()
            self.update_recommendations()
  • Flight change (10 AM → 2 PM): system receives FLIGHT_CHANGE → method processes it → checks effect on hotel bookings/transfers → notifies customer automatically.
  • Weather alert: receives WEATHER_ALERT → evaluates impact on travel → finds alternative dates/destinations → updates recommendations.

(2) State validation and consistency

Ensures the agent's understanding stays accurate: valid state transitions, maintained dependencies, business rules followed — a gatekeeper before state changes are applied.

def validate_state_transition(current_state, new_state):
    if not is_valid_transition(current_state, new_state):
        raise InvalidStateTransition("Invalid transition from {current_state} to {new_state}")
    check_state_dependencies(new_state)
    validate_business_rules(new_state)
CheckExample
Transition validation"on hold" → "confirmed": Is payment received? Seats still available? Price still valid?
Dependency checkingFlight + hotel: hotel check-in after flight arrival; transfer availability matches flight time; room type matches number of travellers.
Business rulesInternational booking: passport information provided; travel insurance offered; cancellation policy acknowledged.

If any check fails, the state change is blocked and an error raised → booking integrity maintained.

B2.4 Monitoring and adaptation

  • Monitoring metrics: latency of state updates; accuracy/precision of predictions and decisions; resource-utilisation patterns; error rates & recovery times; customer-satisfaction indicators.
  • Adaptation strategies: dynamic resource allocation for varying workloads; continuously refine/update models from new data; adjust rules & optimisation parameters (seasonal patterns, preference shifts); performance tuning & scaling; incorporate user feedback.

Success depends on representing state and environment and adapting: consider static + dynamic elements, robust integration patterns, effective monitoring — keeping the agent reliable, efficient and responsive as the environment evolves.

Part B3 — Agent Memory Architecture and Context Management

Memory enables coherent interactions and informed decisions from past experience and current context. Three memory types: short-term, long-term, episodic.

Memory typePurposeTravel agent example
Short-term (working) memoryImmediate cognitive workspace; temporarily holds info for the current interaction/task; conversation context, multi-step processes, active sessions; cleared when session ends or info becomes irrelevant (efficient resource use).Current search criteria, recently viewed options, temporary preferences during the session, booking-process state.
Long-term memory (knowledge base)Persistent repository across interactions/sessions; accumulated knowledge, learned patterns, customer relationships; consistency and personalisation without repeating preferences.Customer preferences over multiple bookings, past travel records, destination knowledge, seasonal patterns, provider relationships.
Episodic memory (interaction history)Stores specific interactions, events and outcomes as discrete episodes with temporal sequence & context; learn from past experience; pattern recognition on behaviour and outcomes; common in conversational interfaces/chatbots.Identify successful booking patterns, common customer journeys; avoid repeat issues (e.g., problem layover times at certain airports).

Implementation sketches

# Short-term memory
class WorkingMemory:
    def __init__(self):
        self.current_interaction = {'customer_id': None, 'session_start': None,
            'current_query': None, 'active_searches': [], 'temporary_preferences': {}}
    def update_context(self, new_information):   # update current interaction context
        self.current_interaction.update(new_information)
    def clear_session(self):                      # reset temporary session data
        self.__init__()
# Long-term memory
class CustomerMemory:
    def __init__(self):
        self.profiles = {'preferences': {}, 'travel_history': [], 'feedback_history': [],
                         'special_requirements': {}, 'loyalty_status': None}
    def update_profile(self, customer_id, new_data):   # merge new info with existing profile
        self.profiles[customer_id] = {**self.profiles.get(customer_id, {}), **new_data}

B3.1 Context management

ScenarioMulti-city business trip to Tokyo & Singapore: corporate policy limits flights to $2,000, preference for morning flights due to meetings, hotels within walking distance of offices — the agent must track and update all of this while moving between flight searches, hotel availability and meeting schedules.

Context hierarchy

LevelContents
Global contextSystem-wide settings & constraints; current operational status; global travel alerts and advisories.
Session contextCurrent customer-interaction state; active searches/queries; temporary preferences & constraints.
Task contextSpecific booking details; current step in multi-step processes; related bookings & dependencies.

Context switching — smooth transition between contexts while preserving coherence:

  • Context preservation: save current state before switching; maintain history of context changes; ensure no critical information is lost.
  • Context restoration: retrieve previous contexts; rebuild operational environment; re-establish relevant connections and states.
  • Context merging: combine information from multiple contexts; resolve conflicts; maintain consistency across changes.

B3.2 Integration with decision-making

  1. Information retrieval — gather/synthesise from memory: customer history & preferences; similar past cases & outcomes; combine current context with history; filter & prioritise.
  2. Pattern recognition — analyse historical interaction patterns; identify successful booking patterns; recognise potential issues from past experience; detect seasonal trends & preferences.
  3. Decision optimisation — weighted evaluation of options; multiple constraints; balance customer preferences vs system requirements; risk assessment and mitigation.

Part B4 — Sequential and Parallel Processing in Agentic Workflows

B4.1 Sequential processing

Tasks handled in a defined order, each step depending on the completion of previous ones. Needed for: (1) Flight & hotel coordination — confirm flight availability before booking hotels; transfers aligned with arrival times; validate visa requirements before finalising; (2) Payment processing — verify funds → process payment → confirm bookings → send confirmation documents.

Drawback: inefficient when many independent operations could run simultaneously.

B4.2 Parallel processing

Multiple independent tasks handled simultaneously → better efficiency and response times. (1) Concurrent searches — multiple airline systems, different hotel chains, weather forecasts & travel advisories; (2) Background processing — update customer profiles, process feedback & reviews, monitor price changes, update travel advisories.

SequentialParallel
Use when tasks have dependencies (payment → confirmation)Use for independent tasks (multi-vendor searches)

An agent must dynamically switch modes depending on task requirements, system load and time constraints → workflow optimisation.

B4.3 Workflow optimisation

  1. Task classification & prioritisation
    • Dependency analysis: critical-path tasks that must be sequential; map dependencies between booking components; data-flow requirements; temporal constraints & deadlines.
    • Priority assignment: urgency/importance; customer SLAs & expectations; impact on overall booking; resource requirements.
  2. Resource management
    • System resources: monitor CPU/memory; balance load across components; throttling; optimise DB connections & caches.
    • External services: track API rate limits/quotas; manage concurrent requests; retry strategies for failures; maintain provider priorities.
  3. Dynamic workflow adjustment
    • Load balancing: adjust parallel execution to load; redistribute during peaks; manage queue depths & processing rates; implement backpressure.
    • Performance monitoring: task completion times & success rates; identify bottlenecks; measure throughput & latency; monitor resource utilisation.

Goal: workflows that are efficient, resilient and adaptable.

Chapter 7 Summary and Q&A

  • Focused system prompts (objective, core functions, constraints, behaviour), task specifications (steps, outputs, challenges), contextual awareness (destination intelligence, dynamic adaptation, cultural competence).
  • State space = moment-in-time view (customer profile, travel context, booking state); environment model = systems, rules, changing conditions (static vs dynamic).
  • Integration patterns: event-driven updates and state validation & consistency; monitoring + adaptation.
  • Memory: short-term (working), long-term (knowledge base), episodic (interaction history); context hierarchy (global/session/task), switching (preservation, restoration, merging).
  • Workflows: sequential for dependent tasks, parallel for independent tasks; optimisation by classification, resource management, dynamic adjustment. (Next chapter: building trust in generative-AI systems.)
Q1. Three memory types & importance? Short-term (immediate context, active search parameters, session state), long-term (persistent profiles, regulations, destination info), episodic (interaction episodes enabling learning & pattern recognition) — maintain context, learn from experience, decide using current + historical info.
Q2. Sequential vs parallel; when in travel booking? Sequential for dependent steps (flight availability before hotel; payment → confirmation); parallel for independent tasks (airline searches, hotel availability, weather forecasts at the same time).
Q3. Context management & levels? Maintains awareness of current situation + history: global, session, task contexts.
Q4. Environment model vs state space? Environment model = external systems, static rules (policies, interfaces) and dynamic elements (availability, pricing); state space = current situation, available actions, outcomes — environment gives the broader context in which the state space exists.
Q5. Factors for sequential vs parallel? Task dependencies, resource availability, time constraints (SLAs), system load, performance requirements (throughput/latency).
